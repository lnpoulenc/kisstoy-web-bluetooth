# KissToy Web Bluetooth

一个适合在 iPhone Bluefy 浏览器中使用的中文蓝牙控制页面，支持 QCSW 与 PLMX 设备的双通道强度调节。

手机通过 BLE 直接控制设备，无需官方 APP、官方 API 或云端控制中转。项目是无依赖的静态网页，仍需通过网站托管提供页面；控制指令由浏览器在本机蓝牙连接中发送。

## 支持的设备

| 蓝牙名称前缀 | 页面型号 | 通道 1 | 通道 2 |
| --- | --- | --- | --- |
| `QCSW` | 迷路 · 吮吸版 | 震动 | 吮吸 |
| `PLMX` | Polly Max | 旋转 | 吮吸 |

以上通道映射来自用户实机测试，具体产品代数未知，其他批次的兼容性仍待验证。页面根据设备名称自动选择协议；若实际通道相反，可在断开连接时使用“交换两个通道”。

设备选择器只筛选名称以 `QCSW` 或 `PLMX` 开头的已知设备，并非附近所有蓝牙设备的扫描器。

## 在 iPhone 上使用

1. 安装 [Bluefy 浏览器](https://apps.apple.com/app/id1492822055)，用它打开已部署页面的受信任 HTTPS 地址。iPhone 上的 Safari、Chrome 无法直接使用本页的网页蓝牙功能。
2. 打开手机蓝牙和设备电源，关闭正在占用设备连接的其他 APP。
3. 点击“连接 / 自动识别设备”，允许蓝牙权限，在系统选择器中选择自己的 `QCSW` 或 `PLMX`。
4. 页面自动识别型号；首次连接不会发送电机控制指令。先从低强度、单个通道开始，确认设备反应。
5. 使用结束后点击“全部停止”，或选择“停止并断开连接”。

每个通道都有 **0 / 25 / 50 / 75 / 100%** 快捷按钮，以及以 **5%** 为步长的滑块。快捷按钮只改变所在通道，另一通道保留上次成功写入的强度；滑块在完成调节后发送。未连接时控制不可用。

“全部停止”停止当前控制设备的两个通道，并取消保存的恢复强度。蓝牙写入成功表示指令已写入连接，不等于设备已执行；请以实机反应为准。

## 我的设备与切换

- 连接后点击“添加 / 识别设备”可添加另一台设备，在“我的设备”列表中点击设备行切换。
- 浏览器支持读取已授权设备时，页面会加载之前授权的 QCSW / PLMX。加载列表不会自动连接，也不会发送控制指令；不支持该接口时，列表仅保留本次页面中选择的设备。
- **已授权不代表在线。** 列表区分“当前控制”“已连接”“未连接”；只有实际 GATT 连接存在时才标为已连接。未连接的记录也可以点击尝试连接。
- 切换前先给上一台发送停止指令；如果停止失败，就中止切换。成功切换后，新设备的控制值从 0 开始，不继承上一台强度。
- 已停止的上一台会尽量保留蓝牙连接，方便再次切换。非当前设备掉线时只更新列表，不会抢回当前控制。

## 断线、恢复与后台运行

意外断线后，页面会尝试自动重连 **5 次**，间隔依次为 1、2、4、8、8 秒。失败后可点击“重新连接”。默认只在前台重连；开启后台继续运行后，也会在浏览器允许时尝试。

“短暂断线后自动恢复强度”默认关闭。重连后会先发送停止指令，可点击“恢复刚才的强度”手动继续；开启此选项后，只有在 **30 秒内**重连成功，才会自动重新写入断线前成功写入的强度。按停止或手动断开会取消恢复。

“切到后台继续运行”也默认关闭：

- 关闭时，切换 APP 或锁屏会尝试停止，并清除恢复强度。
- 开启时，切换 APP 或锁屏不主动停止。可在 Bluefy 设置中查找 **Allowed BLE peripheral manager**，允许相应设备的后台蓝牙连接，再低强度实测。
- 两个开关每次重新打开网页都默认关闭，需要分别开启。

Bluefy 或 iOS 仍可能暂停网页，后台控制与自动重连不保证持续运行。这个静态网页不能启动或接入灵动岛。

关闭、刷新或离开页面会尝试停止；系统挂起或蓝牙已断开时，停止指令可能无法送达。设备仍在运行时，请使用设备实体按键停止。遇到频繁掉线，可展开“连接诊断”查看或复制记录。

## 部署到 GitHub Pages

仓库根目录就是网站目录，无需安装依赖或构建。

1. 将仓库推送到 GitHub，确认 `index.html`、`app.mjs`、`protocol.mjs`、`style.css` 位于 `main` 分支根目录。
2. 打开仓库的 **Settings → Pages**。
3. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
4. 选择分支 **main**、目录 **/(root)**，点击 **Save**。
5. 等待部署完成，将 Pages 显示的 HTTPS 地址复制到 iPhone Bluefy 中打开。

也可部署到其他支持 HTTPS 的静态网站托管服务。页面使用相对资源路径，可部署在 GitHub Pages 的仓库子路径下。

直接下载 HTML 后以 `file://` 打开不受支持。手机访问必须使用受信任的 HTTPS：局域网中的普通 HTTP IP 地址并不属于浏览器给本机 `localhost` 的安全上下文例外。

## 本地开发

电脑上可用 Python 预览页面：

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

在同一台电脑打开 `http://127.0.0.1:8080`。此地址仅用于电脑本机预览，不能作为手机访问地址；蓝牙功能还需要浏览器支持 Web Bluetooth。

测试需要 **Node.js 22 或更新版本**，没有 npm 依赖，无需先运行 `npm install`：

```sh
npm test
```

也可直接执行：

```sh
node --test tests/*.test.mjs
```

测试覆盖协议编码、连接与重连、停止并发、后台处理、快捷档位和设备切换。蓝牙连接使用模拟对象，测试通过不代替不同设备与 iOS 版本的实机验证。

主要文件：

| 文件 | 用途 |
| --- | --- |
| `index.html`、`style.css` | 中文界面与样式 |
| `app.mjs` | 蓝牙连接、设备列表、控制和恢复逻辑 |
| `protocol.mjs` | 协议编码与顺序写入队列 |
| `tests/` | Node.js 内置测试运行器用例 |
| [SOURCES.md](SOURCES.md) | 协议资料、来源链接与改编说明 |
